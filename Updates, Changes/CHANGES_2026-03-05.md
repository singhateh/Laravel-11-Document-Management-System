# Changes — March 5, 2026

## Core Security Architecture Implementation

Implemented the three gaps identified between the StegoLock architecture spec and the
project: Master Key Derivation (MKD) at login, PSNR quality gate in the encode pipeline,
and proper JSON encode/decode endpoints in the API layer.

---

## 1. Master Key Derivation (MKD) — Authenticate Once Per Session

### Problem
The architecture specifies that a user authenticates **once per session** and never types
a per-document passphrase again. The existing `StegoWebController::encode()` and `decode()`
required `master_key` to be POSTed on every operation, violating the UX and security
model (client-transmitted keys in request bodies).

### Fix — Schema

**New migration**: `database/migrations/2026_03_05_000001_add_mkd_salt_to_users_table.php`

Added `mkd_salt VARCHAR(32) NULLABLE` to the `users` table.

```sql
ALTER TABLE users ADD COLUMN mkd_salt VARCHAR(32) NULL
  COMMENT 'PBKDF2-SHA256 salt for Master Key Derivation (hex, 32 chars = 16 bytes)';
```

The salt is generated once at registration. The Master Key itself is **never stored** — 
only the salt is persisted so the key can be re-derived at every login.

**Model update**: `app/Models/User.php`

Added `mkd_salt` to `$fillable`.

### Fix — Register

`app/Http/Controllers/Api/AuthController.php` — injected `CryptoService` via constructor.

```php
// After — register() derives and stores the MKD salt
$mkdResult = $this->crypto->deriveMasterKey($validated['password']);

$user = User::create([
    ...
    'mkd_salt' => $mkdResult['salt'],   // 32 hex chars; Master Key is NOT stored
]);
```

### Fix — Login

```php
// After — login() re-derives the Master Key and stores it server-side in the session
if ($user->mkd_salt) {
    $mkdResult = $this->crypto->deriveMasterKey(
        $request->password,
        $user->mkd_salt,
        (int) config('stegolock.mkd_iterations', 100_000)
    );
    session(['stego_mkd' => $mkdResult['masterKey']]);
}
```

The hex-encoded Master Key lives only in the **server-side Laravel session** (encrypted
at rest by the session driver). It is never returned to the client and never written to
the database.

**Files changed**: `app/Models/User.php` (+1 fillable),
`app/Http/Controllers/Api/AuthController.php` (+constructor injection, +5 lines in
`register()`, +8 lines in `login()`),
`database/migrations/2026_03_05_000001_add_mkd_salt_to_users_table.php` (new).

## 2. Session-Key Usage in Web UI — Remove Per-Request `master_key`

### Problem
`StegoWebController::encode()` and `decode()` both validated a `master_key` field from
the request body, meaning the client had to know and transmit the key on every call.

### Fix

`app/Http/Controllers/StegoWebController.php`

Removed `master_key` from the validation rules in both methods. Both now read the key
from the server-side session instead:

```php
// Before — required field in every request
'master_key' => ['required', 'string', 'min:8'],

// After — sourced from session; request field gone entirely
$masterKey = session('stego_mkd');
if (empty($masterKey)) {
    return back()->withErrors([
        'session' => 'Session expired. Please log in again to obtain a fresh Master Key.',
    ]);
}
```

If the session has expired the user receives a clear error directing them to log in again.

**Files changed**: `app/Http/Controllers/StegoWebController.php` (encode + decode).

## 3. PSNR Quality Gate in the Encode Pipeline

### Problem
`StegoService::psnr()` existed but was never called. The architecture requires PSNR ≥
40 dB for image carriers ("imperceptibility threshold"). There was no enforcement and no
per-carrier quality data stored in the database.

### Fix — Schema

**New migration**: `database/migrations/2026_03_05_000002_add_psnr_to_stego_carriers_table.php`

Added `psnr FLOAT(8,4) NULLABLE` to `stego_carriers`.

```sql
ALTER TABLE stego_carriers ADD COLUMN psnr FLOAT(8,4) NULL
  COMMENT 'PSNR in dB measured after LSB embedding (images only; null otherwise)';
```

**Model update**: `app/Models/StegoCarrier.php` — added `psnr` to `$fillable`.

### Fix — Quality Gate in `StegoDocumentService::encode()`

`app/Services/Stego/StegoDocumentService.php`

After each `stego->embed()` call, if the carrier is an image, PSNR is measured and
enforced before the carrier is uploaded to S3:

```php
$mime = mime_content_type($carrierPath) ?: '';
if (str_starts_with($mime, 'image/')) {
    $metrics = $this->stego->psnr($carrierPath, $outputPath);
    if (!$metrics['threshold_40db']) {
        throw new Exception(sprintf(
            'Carrier "%s": PSNR %.2f dB is below the 40 dB imperceptibility threshold. '
            . 'Choose a larger carrier image.',
            basename($carrierPath), $metrics['psnr']
        ));
    }
    $psnrValue = $metrics['psnr'];
}
```

Non-image carriers (audio, binary) are exempt — PSNR is stored as `null`.

### Changed return type of `encode()`

`encode()` previously returned `StegoDocument`. It now returns:

```php
return [
    'stego_document'  => $stegoDoc->fresh(),
    'quality_metrics' => array_values($qualityMetrics),
];
```

Where `quality_metrics` is an array of `{ carrier, psnr, threshold_40db }` objects —
one per carrier — intended for display in the UI and API response.

`StegoWebController::encode()` updated to unpack `$result['stego_document']`.

**Files changed**: `app/Models/StegoCarrier.php` (+1 fillable),
`app/Services/Stego/StegoDocumentService.php` (PSNR gate + new return shape),
`app/Http/Controllers/StegoWebController.php` (unpack array return),
`database/migrations/2026_03_05_000002_add_psnr_to_stego_carriers_table.php` (new).

## 4. JSON API Encode/Decode Endpoints

### Problem
`POST /api/stego/encode` and `POST /api/stego/decode` were pointing to
`StegoWebController` which returns Inertia redirects — not JSON. The SPA/API clients
received redirect responses instead of structured JSON.

### Fix — New methods in `Api\StegoDocumentController`

`app/Http/Controllers/Api/StegoDocumentController.php`

Added constructor injection of `StegoDocumentService`. Added two new methods:

#### `encode(Request $request): JsonResponse`

| Field | Description |
|-------|-------------|
| Input | `document_id` (int), `carriers[]` (PNG/BMP files ≤ 20 MB) |
| Auth | Reads `session('stego_mkd')` — returns `401` if expired |
| Response `201` | `stego_document_id`, `document_id`, `document_name`, `segments_count`, `quality_metrics[]`, `created_at` |
| Response `422` | `{ message }` on encoding failure (including PSNR gate rejection) |

#### `decode(Request $request): StreamedResponse|JsonResponse`

| Field | Description |
|-------|-------------|
| Input | `stego_document_id` (int) |
| Auth | Reads `session('stego_mkd')` — returns `401` if expired |
| Ownership | Scoped query — `404` if not owned by authenticated user |
| Response `200` | Binary file download (`application/octet-stream`) |
| Response `422` | `{ message }` on decryption or integrity failure |

### Fix — routes/api.php

Removed `use App\Http\Controllers\StegoWebController` import (no longer needed in the
API routes file). Updated the two POST routes:

```php
// Before
Route::post('/encode', [StegoWebController::class, 'encode'])->name('encode');
Route::post('/decode', [StegoWebController::class, 'decode'])->name('decode');

// After
Route::post('/encode', [StegoDocumentController::class, 'encode'])->name('encode');
Route::post('/decode', [StegoDocumentController::class, 'decode'])->name('decode');
```

**Files changed**: `app/Http/Controllers/Api/StegoDocumentController.php`
(+constructor, +`encode()`, +`decode()`), `routes/api.php` (-1 import, 2 route targets
updated).

## 5. DRY — `HasStegoEncoding` Trait

### Problem
`Api\StegoDocumentController` and `StegoWebController` contained five identical inline
helper blocks:

- Reading the session Master Key and returning an error if absent
- Moving uploaded carrier files to temp paths
- Unlinking temp carrier files in `finally` blocks
- Reading document plaintext from storage
- Building the download filename from a `StegoDocument` relationship

### Fix

**New file**: `app/Http/Concerns/HasStegoEncoding.php`

```
Trait HasStegoEncoding
├── resolveSessionKey(): ?string         — reads session('stego_mkd'), null if empty
├── storeCarriersTmp(array): array       — moves UploadedFiles to sys_get_temp_dir()
├── releaseCarriers(array): void         — unlinks temp files (safe, ignores missing)
├── readDocumentPlaintext(Document): string  — Storage::disk('local')->get() + error
└── buildDecodeFilename(StegoDocument): string — null-safe name+extension fallback
```

Both controllers import the trait (`use HasStegoEncoding`) and call the helpers
directly. All five duplicated blocks were removed.

**Also fixed**: `readDocumentPlaintext()` reads via `Storage::disk('local')` rather than
raw `file_get_contents(storage_path(...))`, making it compatible with `Storage::fake()`
in feature tests.

**Files changed**: `app/Http/Concerns/HasStegoEncoding.php` (new),
`app/Http/Controllers/Api/StegoDocumentController.php` (5 blocks → trait calls),
`app/Http/Controllers/StegoWebController.php` (5 blocks → trait calls).

## 7. Session Key Guard — Moved Before Validation

### Problem
In `Api\StegoDocumentController`, the session key check ran *after* `$request->validate()`.
A client with an expired session but an incomplete payload would receive `422 Validation
Failed` instead of the correct `401 Session Expired`.

### Fix

**File**: `app/Http/Controllers/Api/StegoDocumentController.php`

`resolveSessionKey()` (and the `401` early return) moved to the **first line** of both
`encode()` and `decode()`, before `$request->validate()` is called.
