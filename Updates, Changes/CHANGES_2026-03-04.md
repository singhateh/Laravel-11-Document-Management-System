# Changes — March 4, 2026

## 1. DRY & Refactoring Pass — API Layer

### Overview
Applied DRY (Don't Repeat Yourself) and single-responsibility principles across the API layer.
Three categories of duplication were eliminated: a repeated 10-field audit log block, a triple
service-method call, and six route closures that owned business logic. No external behaviour was
changed.

---

### 1.1 `AccessLog::log()` — Eliminate Audit Block Duplication

**Problem**: Every audit write required an identical 10-field `AccessLog::create([...])` block.
The block appeared **4 times** across two controllers, differing only in `action`, `resource_id`,
and `status_code`. The other 7 fields (`user_id`, `ip_address`, `user_agent`, `method`, `url`,
`accessed_at`, `resource`) were identical boilerplate every time.

**Fix**: Added a static `log()` factory method to `app/Models/AccessLog.php`.

```php
// Before — 10 lines per call site (×4 = 40 lines total)
AccessLog::create([
    'user_id'     => Auth::id(),
    'action'      => 'download',
    'resource'    => 'document',
    'resource_id' => $document->id,
    'ip_address'  => request()->ip(),
    'user_agent'  => request()->userAgent(),
    'method'      => request()->method(),
    'url'         => request()->fullUrl(),
    'status_code' => 200,
    'accessed_at' => now(),
]);

// After — 1 line per call site
AccessLog::log('download', 'document', $document->id, request());
```

**Signature**:
```php
AccessLog::log(
    string $action,
    string $resource,
    string|int|null $resourceId,
    Request $request,
    int $statusCode = 200
): void
```

Derives `user_id`, `ip_address`, `user_agent`, `method`, `url`, `accessed_at` automatically from
`Auth::id()` and the injected request.

**Files changed**: `app/Models/AccessLog.php` (+28 lines), all 4 call sites reduced to 1 line each.

### 1.2 `DocumentController::getFiles()` — Eliminate Triple Service Call

**Problem**: `getFiles()` called `$this->documentService->getFolderFiles($folder, $tags)` **three
times** with identical arguments to destructure its three return keys, causing 3 redundant DB
round-trips on every request.

```php
// Before — service invoked 3× (3 DB round-trips)
$documents  = $this->documentService->getFolderFiles($folder, $tags)['documents'];
$folderInfo = $this->documentService->getFolderFiles($folder, $tags)['folderInfo'];
$folderData = $this->documentService->getFolderFiles($folder, $tags)['folderData'];
```

**Fix**: Call once, assign to `$result`, then read keys from the single return value.

```php
// After — service invoked 1×
$result = $this->documentService->getFolderFiles($folder, $tags);

return response()->json([
    'documents'  => $result['documents'],
    'folderInfo' => $result['folderInfo'],
    'folders'    => $result['folderData'],
    'folder_id'  => $folder,
]);
```

**Files changed**: `app/Http/Controllers/DocumentController.php`.

### 1.3 Route Closures → Dedicated Controllers

**Problem**: `routes/api.php` contained **6 closures** that owned query and business logic inline:

| Closure | Lines | Business logic |
|---------|-------|----------------|
| `GET /api/stego/documents` | 7 | Paginated stego doc list |
| `GET /api/stego/documents/{id}` | 7 | Single stego doc + segments |
| `GET /api/stego` (SPA alias) | 3 | Duplicate stego list |
| `DELETE /api/stego/{id}` | 4 | Ownership-scoped delete |
| `GET /api/dashboard/stats` | 8 | Aggregate counts |
| `GET /api/dashboard/recent` | 7 | Recent docs with tags |

Route files should be thin declarations. Logic in closures cannot be unit-tested, cached by
`route:cache`, or extended by policies without rewriting the route file.

**Fix**: Extracted logic into two new dedicated controllers.

#### New file: `app/Http/Controllers/Api/StegoDocumentController.php`

| Method | Route | Description |
|--------|-------|-------------|
| `index()` | `GET /api/stego/documents` + `GET /api/stego` alias | Paginated list with `document:id,name,extension` eager load + `withCount('segments')` |
| `show()` | `GET /api/stego/documents/{id}` | Single record with full `document` + `segments`, scoped to authenticated user |
| `destroy()` | `DELETE /api/stego/{id}` | Ownership-scoped delete |

The `/api/stego` SPA alias now reuses `StegoDocumentController::index()` directly — the previously
duplicated closure with slightly different eager loading is unified into a single consistent query.

#### New file: `app/Http/Controllers/Api/DashboardController.php`

| Method | Route | Description |
|--------|-------|-------------|
| `stats()` | `GET /api/dashboard/stats` | Returns counts: `documents`, `folders`, `categories`, `tags`, `stego_documents` |
| `recent()` | `GET /api/dashboard/recent` | Returns 8 most recent docs with tags and `is_stegoed` flag |

#### Modified: `routes/api.php`

- Added imports: `DashboardController`, `StegoDocumentController`
- Removed 6 now-unused imports: `Document`, `Folder`, `Category`, `Tag`, `StegoDocument`, `Auth` facade
- All 6 closures replaced with `[Controller::class, 'method']` references
- `GET /api/documents` inline closure also replaced with `[ApiDocumentController::class, 'index']`

Route file line count: **180 → 119 lines** after removing closure bodies and unused imports.

## 2. Route Fix — StegoLock SPA Shell

**Problem**: The `/stego-app/{any?}` route was registered inside the `auth` middleware group,
causing guests to be redirected to `/login` before the SPA could load. The SPA handles its own
authentication internally and must be publicly accessible.

**Fix**: Moved the route outside the `auth` middleware group in `routes/web.php`.

```php
// After — public (no auth middleware)
Route::get('/stego-app/{any?}', fn () => view('stegolock'))
    ->where('any', '.*')
    ->name('stego.spa');
```

**File changed**: `routes/web.php`.

## 3. Vite Dev Server — Allow All Hosts

**Problem**: Vite's development server blocked requests from non-`localhost` origins (e.g. LAN IP,
tunnels), causing HMR and asset loading to fail when accessing the app from another device or
via a proxy.

**Fix**: Added `server.allowedHosts: 'all'` to `vite.config.js`.

```js
export default defineConfig({
    server: {
        allowedHosts: 'all',
    },
    // ...
});
```

**File changed**: `vite.config.js`.

## 4. New Utility: `check-routes.ps1` — Laravel Route Health Checker

### Overview
Added a PowerShell script that probes every registered route and asserts the expected HTTP status
code, providing a fast sanity-check before and after deployments or refactoring.

### Usage

```powershell
.\check-routes.ps1                              # uses http://127.0.0.1:8000
.\check-routes.ps1 -BaseUrl http://localhost:8000
```

### Routes Covered

| Category | Routes checked | Expected status |
|----------|---------------|-----------------|
| Public web | `/`, `/up`, `/stego-app`, `/login`, `/register` | `200` |
| Auth-guarded web | `/documents`, `/folders`, `/dashboard`, `/profile`, `/tags`, `/categories`, `/search`, `/stego`, `/home`, `/projects`, `/contacts` | `302` (redirect to login for guests) |
| API public | `/api/health`, `POST /api/auth/login`, `POST /api/auth/register` | `200` / `422` |
| API auth-guarded | `/api/auth/me`, `/api/auth/logout`, `/api/auth/tokens`, `/api/documents`, `/api/documents/1`, `POST /api/documents`, `/api/stego/documents`, `/api/stego`, `/api/dashboard/stats`, `/api/dashboard/recent`, `POST /api/stego/encode`, `POST /api/stego/decode` | `401` |
| Edge cases | Unknown web route, unknown API route, wrong HTTP method | `2xx/302/404`, `404`, `405` |

### Output

```
[  OK  ]  GET /api/health                       got 200  (expected 200)  # JSON health
[ FAIL ]  GET /api/documents                    got 500  (expected 401)
```

Exits with a summary line: `Summary: 28/29 passed`.

**New file**: `check-routes.ps1`.
