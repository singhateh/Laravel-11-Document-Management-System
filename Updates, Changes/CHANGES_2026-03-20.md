## 1. SHA-256 (Truncated) Column Not Displaying in My Stego Documents Table

### Problem
The SHA-256 (truncated) column in the "My Stego Documents" table was showing dashes ("—") instead of the truncated SHA-256 hash of each document. This was because the `stego_hash_sha256` field was not being included in the select statement of the stego document index queries.

### Fix
Updated both API and web controllers to include the `stego_hash_sha256` field in their select statements:

#### File 1: app/Http/Controllers/Api/StegoDocumentController.php
```php
// Before
->select([
    'id',
    'document_id',
    'user_id',
    'status',
    'decoding_status',
    'download_path',
    'created_at',
    'updated_at',
])

// After
->select([
    'id',
    'document_id',
    'user_id',
    'status',
    'decoding_status',
    'download_path',
    'created_at',
    'updated_at',
    'stego_hash_sha256', // Added
])
```

#### File 2: app/Http/Controllers/StegoWebController.php
```php
// Before
->select([
    'id',
    'document_id',
    'user_id',

    'decoding_status',
```

## 2. AES-256-GCM Decryption Issue (Authentication Tag Mismatch)

### Problem
The `decrypt` method in `CryptoService` was failing with an "authentication tag mismatch or corrupt data" error. This was because:
- The `encrypt` method base64-encoded the ciphertext before storing it
- The `decrypt` method was expecting raw binary input but received the base64-encoded string directly

### Fix
Updated the `decrypt` method in `app/Services/Stego/CryptoService.php` to handle both base64-encoded ciphertext (from legacy DB/local file) and raw binary (from segments):

```php
// Check if ciphertext is base64-encoded (legacy DB/local file) or raw binary (segments)
$ciphertextBinary = base64_decode($ciphertext, true);
if ($ciphertextBinary === false) {
    // If base64 decode fails, assume it's raw binary from segments
    $ciphertextBinary = $ciphertext;
}

if (empty($ciphertextBinary)) {
    throw new Exception('Ciphertext cannot be empty');
}

$compressed = openssl_decrypt(
    $ciphertextBinary, // Now passes raw binary to openssl_decrypt
    self::CIPHER,
    $dekBinary,
    OPENSSL_RAW_DATA,
    $ivBinary,
    $authTagBinary
);
```

### Verification
All tests passed successfully, confirming that the fix resolves the authentication tag mismatch issue.
