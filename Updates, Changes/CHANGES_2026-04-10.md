# CHANGES - 2026-04-10

## Summary
This update focused on clarifying stego document lifecycle states, preventing decode attempts on non-ready records, improving UI transparency for pending/failed encode outcomes, and fixing folder ordering display issues.

Additional storage alignment changes were applied to reduce Backblaze latency during document processing.

## Fixes
- Fixed ambiguous stego list behavior where a row could show hash/timestamp with `0 carriers` by surfacing processing status in UI.
- Added server-side guardrails to block decode requests unless stego document status is `ready`.
- Added explicit error messaging for non-ready decode attempts, including failure reason when available.
- Removed Backblaze persistence for stego ciphertext binaries; ciphertext now remains local in DB for fallback/decode compatibility.
- Switched frontend document upload utility from B2 direct-upload flow to local multipart upload route (`/upload`) so source uploads no longer traverse Backblaze.
- **FIXED: Folders now display actual document/folder names instead of internal numeric position values
- **FIXED: Default folder ordering now uses alphabetical sort by name instead of internal sequence position
- **FIXED: Right sidebar folder list now sorted alphabetically

## Changes
- API stego index now supports optional status filtering:
  - `pending`
  - `ready`
  - `failed`
- API responses now include additional lifecycle context (`status`, `failed_reason`) used by frontend.
- SPA decode list now fetches only ready stego documents (`/api/stego?status=ready`).
- Web decode form now lists only ready stego documents.
- Stego index pages (SPA + Inertia) now show status badges and failed reason snippets.
- Stego index cache invalidation expanded to clear status-specific cache keys.
- Stego encode now stores ciphertext in `stego_documents.ciphertext` and keeps `stego_documents.s3_key` null for new records.
- Final stego artifacts (segment/derived stego files) still upload through `CloudStorageService` to the configured Stego storage disk (e.g., B2).
- Carrier pool behavior is unchanged: carrier pool files continue to use storage-backed persistence.
- **CHANGED: Folder model global default ordering from numeric position → alphabetical name sort
- **CHANGED: All folder listings, menus and dropdowns now display in alphabetical order

## Notes
