# Changes — March 3, 2026

## 1. Python Stegano Library Integration

### Overview
Replaced the custom PHP GD-based LSB steganography engine with the Python `stegano` library, bridged through a PHP subprocess call via `symfony/process`. A driver toggle allows switching back to the PHP engine without code changes.

### New Files

#### `python/stego_lsb.py`
Python bridge script wrapping `stegano.lsb`. Accepts three commands dispatched via `argv[1]`:

| Command | Input | Output |
|---------|-------|--------|
| `embed` | carrier path, payload (base64), output path | JSON `{ success, data: output_path }` |
| `extract` | stego-image path | JSON `{ success, data: base64_payload }` |
| `capacity` | image path | JSON `{ success, data: byte_count }` |

Binary payloads are base64-encoded before embedding (stegano requires string input) and decoded after extraction. Capacity formula accounts for ~33% base64 overhead: `(w × h × 3) // 8 × 3/4`.

#### `config/stegolock.php`
Centralized StegoLock configuration file.

| Key | Env Variable | Default |
|-----|-------------|---------|
| `driver` | `STEGO_DRIVER` | `python` |
| `python_path` | `PYTHON_PATH` | `python` |
| `python_script` | — | `base_path('python/stego_lsb.py')` |
| `python_timeout` | `PYTHON_TIMEOUT` | `60` |
| `mkd_iterations` | `STEGOLOCK_MKD_ITERATIONS` | `100000` |
| `dek_iterations` | `STEGOLOCK_DEK_ITERATIONS` | `10000` |
| `max_carrier_size_mb` | `STEGOLOCK_MAX_CARRIER_MB` | `20` |

### Modified Files

- Updated public `embed()`, `extract()`, `capacity()` methods to branch on `isPythonDriver()` — falls back to PHP GD if driver is not `python`

## 2. Document At-Rest Encryption (AES-256-GCM + DEK)

### Overview
Regular uploaded documents were stored as plaintext on disk. This change introduces AES-256-GCM encryption at rest using a per-document Data Encryption Key (DEK) derived from a master key via PBKDF2-SHA256. The existing `CryptoService` (previously used only in the StegoLock pipeline) is now integrated into the standard document upload and download flow.

### Encryption Architecture

```
DOCUMENT_MASTER_KEY  (env, 256-bit hex)
        │
        ▼
CryptoService::deriveDEK(masterKey, documentId)
        │  PBKDF2-SHA256, 10 000 iterations, per-doc salt
        ▼
   Document DEK  ──►  AES-256-GCM encrypt(plaintext)
                              │
                        ┌─────┴──────┐
                        │            │
                  ciphertext      IV + auth_tag
                  (overwrites      (stored in
                   disk file)    documents table)
```

### New Files

#### `database/migrations/2026_03_03_000001_add_encryption_columns_to_documents_table.php`
Adds the following columns to the `documents` table:

| Column | Type | Description |
|--------|------|-------------|
| `is_encrypted` | `boolean` (default `false`) | Whether the file on disk is encrypted |
| `enc_iv` | `string(24)` | AES-GCM initialization vector (base64) |
| `enc_auth_tag` | `string(32)` | GCM authentication tag (hex) |
| `enc_dek_salt` | `string(32)` | PBKDF2 salt used to derive the DEK (hex) |
| `enc_dek_iterations` | `unsignedInteger` | PBKDF2 iteration count |
| `enc_hash_sha256` | `string(64)` | SHA-256 hash of original plaintext (hex) |

> **Migration status**: ✅ Migrated — batch 2, confirmed via `php artisan migrate:status`.

### Modified Files

#### `app/Models/Document.php`
- Added encryption columns to `$fillable`
- Added `casts()` method: `is_encrypted` → `boolean`, `enc_dek_iterations` → `integer`
- Added `hasPhysicalFile(): bool` helper — returns `false` for URL-type documents (YouTube links, external URLs), skipping them from encryption

#### `app/Services/DocumentService.php`
- Added `use App\Services\Stego\CryptoService`
- Added constructor injection: `public function __construct(private readonly CryptoService $crypto) {}`
- Added `isEncryptionEnabled(): bool` — checks whether `DOCUMENT_MASTER_KEY` is set in the environment
- Added `getMasterKey(): string` — reads the key, throws `RuntimeException` if missing
- Added `encryptDocumentFile(Document $document): void`:
  - Reads plaintext file from disk
  - Derives a per-document DEK via `CryptoService::deriveDEK(masterKey, documentId)`
  - Encrypts with AES-256-GCM
  - Overwrites file on disk with raw ciphertext
  - Updates document record with IV, auth tag, DEK salt, iteration count, and SHA-256 hash
- Added `decryptDocumentContent(Document $document): string`:
  - Returns plaintext directly for non-encrypted (legacy) documents
  - Redirects URL-type documents (returns URL string for controller to redirect)
  - Reconstructs DEK from stored salt + master key, decrypts, verifies SHA-256 hash
- Called `encryptDocumentFile()` after `$document->save()` in all three upload paths: `uploadFolder()` and both branches of `uploadFiles()`

#### `app/Http/Controllers/DocumentController.php`
- Added `use Illuminate\Support\Facades\Auth`
- Added `download(Document $document)` method:
  - Authorizes access (checks ownership for private documents)
  - Handles URL-type documents with a redirect
  - Calls `DocumentService::decryptDocumentContent()` to obtain plaintext
  - Streams file to browser with correct MIME type and filename headers
  - Sets `X-Encryption-Status: AES-256-GCM` or `plaintext` response header

#### `routes/web.php`
```php
Route::get('/documents/{document}/download', [DocumentController::class, 'download'])
    ->name('documents.download');
```

#### `.env`
```env
DOCUMENT_MASTER_KEY=75b8ae49fd372d24710c13e7412e1741a9bac06be07b5d5631a499b270a1e9b2
```

> **Important**: Do not regenerate this key after any documents have been encrypted — doing so makes all existing encrypted files permanently unreadable.

### Backward Compatibility
- Existing documents have `is_encrypted = false` (column default) and are served directly without decryption
- URL-type documents are skipped by both `encryptDocumentFile()` and `decryptDocumentContent()` via `hasPhysicalFile()`
- No changes to the upload API surface — encryption is transparent to callers
